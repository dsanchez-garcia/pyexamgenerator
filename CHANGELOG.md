## [Unreleased]

### Añadido
- **Generación con la API de varios proveedores (Gemini, OpenAI y Anthropic):** nuevo módulo `pyexamgenerator.ai_providers` con clientes para la API de Google Gemini (claves creadas en Google AI Studio, con un nivel gratuito limitado), la API de OpenAI (modelos de ChatGPT) y la API de Anthropic (modelos de Claude). `QuestionGenerator(api_key, model_name, provider=...)` acepta `"gemini"` (por defecto), `"openai"` o `"anthropic"`, además de alias como `"google"`, `"ai studio"`, `"chatgpt"` o `"claude"`. Cada SDK se importa solo cuando se usa: `google-genai` se sigue instalando por defecto y `openai`/`anthropic` se instalan con los extras `pip install pyexamgenerator[openai]`, `pyexamgenerator[anthropic]` o `pyexamgenerator[ia]` (ambos). Si no se indica la clave, se lee de la variable de entorno del proveedor: `GEMINI_API_KEY` o `GOOGLE_API_KEY`, `OPENAI_API_KEY` y `ANTHROPIC_API_KEY`.
- **Salida JSON estructurada con reserva automática:** cuando el modelo lo admite, se pide a la API una respuesta JSON que cumpla un esquema (`question_parsing.QUESTIONS_JSON_SCHEMA`); si el modelo o el SDK instalado no lo admiten, la petición se repite automáticamente como texto normal.
- **Errores claros en español:** la clave no válida, la cuota o el límite de peticiones excedido (429), los servidores saturados (5xx/529), el modelo inexistente, la petición rechazada (400: documento demasiado grande, formato no admitido...) y la librería del proveedor sin instalar se notifican con un mensaje explicativo y sugerencias, mediante las excepciones `InvalidAPIKeyError`, `QuotaExceededError`, `ServiceOverloadedError`, `ModelNotFoundError`, `InvalidRequestError` y `ProviderNotAvailableError` (todas derivan de `AIProviderError`). Una petición rechazada no se repite en cada intento y fragmento, y el saldo o crédito insuficiente se notifica como un problema de cuota. Si no se genera ninguna pregunta, el aviso final muestra el último error de la API.
- **Modo de entrada `pdf`:** además de `text` e `image`, el propio PDF (o cada fragmento, si se activa "Procesar PDF por fragmentos") se envía al modelo como documento adjunto. Funciona con los tres proveedores.
- **Contexto completo opcional en cada fragmento:** nuevo parámetro `include_full_document_context` y casilla **"Incluir el documento completo como contexto en cada fragmento (modo 'text')"**; al desmarcarla, cada prompt lleva solo su fragmento (ahorra tokens y acorta los prompts que se copian en los chats web).
- **Sección "Proveedor de IA, Clave API y Modelo" en la pestaña Generar Preguntas:** selector **"Proveedor"**, campo **"Clave API"** con los botones **"Guardar Clave"** (guarda la clave del proveedor seleccionado junto con el modelo en el `config.json` de la configuración de usuario; ver *Seguridad*), **"Cargar Modelos"** (lista los modelos del proveedor seleccionado) y **"Obtener clave..."** (abre la página del proveedor donde se crean las claves), un desplegable editable **"Modelo"** con modelos sugeridos (Gemini: `gemini-flash-latest`, `gemini-3.8-flash`, `gemini-3.5-flash-lite`, `gemini-pro-latest`; OpenAI: `gpt-6.1-sol`, `gpt-6-luna`, `gpt-6-astra`; Anthropic: `claude-opus-5-5`, `claude-sonnet-5-5`, `claude-haiku-5-5`, `claude-fable-5-1`) y la tabla de modelos. La variable de entorno del proveedor tiene prioridad sobre `config.json`, y el formato antiguo `{"api_key": ...}` se sigue leyendo como clave de Gemini. El menú **Ayuda** añade **"Obtener clave API del proveedor seleccionado..."**.
- **Botón "Cancelar" en la generación:** detiene la generación tras la petición en curso y guarda las preguntas obtenidas hasta ese momento (en scripting, parámetros `cancel_event` y `progress_callback` de `generate_multiple_choice_questions`).
- **Generación sin API (copiar y pegar en el chat del navegador):** nueva sección **"Generar sin API (Google AI Studio, ChatGPT o Claude en el navegador)"** en la pestaña Generar Preguntas. El botón **"Preparar prompts sin API..."** abre el asistente **"Generar preguntas sin API (copiar y pegar en el chat)"** (nuevo módulo `pyexamgenerator.web_chat_assistant`) con selector de chat (Google AI Studio, ChatGPT o Claude), **"Abrir chat en el navegador"**, **"Copiar esquema JSON"** (para *Run settings > Structured output* de Google AI Studio), consejos para cada chat, una tabla con un prompt por PDF/fragmento (y el archivo que hay que adjuntar en los modos `image`/`pdf`; los fragmentos se escriben en la carpeta `<nombre>_adjuntos`), **"Copiar prompt"**, **"Abrir carpeta del adjunto"**, **"Copiar petición de continuación"** (pide más preguntas, o que termine una respuesta cortada, en un bloque JSON nuevo y completo), un cuadro para la respuesta con **"Pegar del portapapeles"**, **"Cargar desde archivo..."**, **"Comprobar respuesta"** (cuenta las preguntas válidas y no válidas) y **"Borrar"**, y los botones **"Exportar prompts y respuestas (Excel + TXT)..."** y **"3. Guardar preguntas (Excel + DOCX)"**, que escribe los mismos archivos que la generación con API.
- **Exportar e importar prompts y respuestas:** `QuestionGenerator.export_prompts(...)` guarda `<nombre>_prompts.xlsx` (con una columna `Respuesta` donde pegar la respuesta del chat) y una carpeta `<nombre>_prompts/` con un `.txt` por prompt; `import_questions_from_prompts_file(...)` lee ese Excel (cada celda de `Respuesta` puede contener la respuesta o la ruta a un `.txt` con ella) e `import_questions_from_responses(...)` acepta las respuestas como texto, lista, diccionario `{tema: texto}` o DataFrame. Ambos escriben `<nombre>_pendiente_de_revisar.xlsx/.docx`, `<nombre>_similares_descartadas.docx` y `<nombre>_no_validas.xlsx` igual que la generación con API. En la GUI, botón **"Importar respuestas desde Excel de prompts..."**. `build_generation_prompts(...)` admite los modos `text`, `image` y `pdf` con las mismas opciones de fragmentación que la generación con API, y `QuestionGenerator()` se puede crear sin clave ni modelo para este flujo.
- **Lectura robusta de las respuestas del modelo:** nuevo módulo `pyexamgenerator.question_parsing`, usado tanto con API como al pegar respuestas de un chat. Acepta arrays JSON, bloques ```` ```json ```` (también varios, p. ej. tras pedir al chat que continúe, aunque el primero quedara cortado sin cerrar o se mezclen respuestas con y sin bloque de código), respuestas cortadas (se conservan las preguntas completas), opciones dadas como objetos (`{"letra": "A", "texto": "..."}`), objetos que envuelven la lista (`{"preguntas": [...]}`), claves en inglés o en `snake_case`, opciones como diccionario o con prefijos `A) `, la respuesta correcta como letra, como `"Opción B"` o como el texto de la opción, y el formato antiguo de diccionarios de Python. Nuevo método `QuestionGenerator.parse_questions_from_text(...)` para convertir una respuesta en un DataFrame sin guardar archivos.
- **Informe de preguntas no válidas:** las preguntas que no se pueden usar (sin 4 opciones distintas y no vacías, o con una respuesta correcta ambigua o no válida, como un número `1` o `"2"`) ya no se aceptan en silencio: se guardan con su motivo en `<nombre>_no_validas.xlsx`.
- **Nuevas pruebas:** `tests/test_multi_provider_unit.py` cubre el parser (formatos de API y de chat, respuestas cortadas, alias de claves, respuestas numéricas y opciones repetidas), los alias de proveedor y las claves en variables de entorno, los clientes de Gemini, OpenAI y Anthropic (adjuntos, salida JSON y su reserva, traducción de errores), la generación con cualquier proveedor y modo de entrada, el guardado parcial ante un error de cuota, la cancelación y el flujo sin API completo (exportar prompts e importar respuestas con filtro de similitud). `tests/test_review_fixes_exam_bank.py` y `tests/test_review_fixes_grading.py` añaden pruebas de regresión para cada fallo corregido en la generación de exámenes, el banco de preguntas y la corrección.

### Cambiado
- **Prompts con formato JSON estricto:** los prompts piden un array JSON con las claves `"Pregunta"`, `"Opciones"` (4), `"Respuesta correcta"` (A-D) y `"Texto relevante"` (en los chats web, dentro de un bloque ```` ```json ````) en lugar de diccionarios de Python, y piden evitar opciones que dependan de su posición (como "todas las anteriores"), porque las respuestas se barajan en los exámenes.
- **Generación en segundo plano:** la generación con API se ejecuta en un hilo aparte, por lo que la ventana ya no se congela; la barra de estado muestra el progreso y el mensaje final indica los archivos guardados.
- **Guardado parcial ante errores:** si la API devuelve un error a mitad del proceso (p. ej. cuota excedida) o falla algo inesperado (un PDF ilegible, un archivo bloqueado), se guardan todas las preguntas obtenidas hasta ese momento (también las del fragmento en curso) antes de mostrar el error. Los archivos fuente que no existen o con un formato que el modo de entrada no admite se detectan antes de la primera llamada a la API.
- **Imágenes BMP, TIFF y GIF:** se convierten a PNG antes de enviarlas a la API, porque no todos los proveedores las admiten.
- **Aviso de prompts muy largos:** si algún prompt sin API supera los 50.000 caracteres, la aplicación avisa (y sugiere fragmentos más pequeños, el modo `pdf` o desmarcar el contexto completo) antes de abrir el asistente.
- **"Prompt Seleccionado" editable:** el texto del prompt de la pestaña Generar Preguntas se puede modificar para una sola generación; para guardarlo de forma permanente se usa **"Editar"**.
- **`QuestionGenerator` sin clave obligatoria:** `api_key` y `model_name` pasan a ser opcionales (solo se necesitan para llamar a la API); el cliente del proveedor se crea en la primera petición.
- **Filtro de similitud:** ignora las tildes al comparar enunciados y es más rápido (las palabras de cada pregunta del banco se calculan una sola vez).
- **Pestaña Generar Preguntas adaptable:** su contenido se ajusta al ancho de la ventana.
- **Nombre de salida por defecto:** si el nombre base de los archivos generados está vacío, se usa `preguntas`.
- **Dependencias:** `pypdf` sustituye a `PyPDF2` (que se sigue usando como alternativa si `pypdf` no está instalado); se elimina `ttkwidgets`, que no se usaba; nuevos extras `[openai]`, `[anthropic]` e `[ia]`; `python_requires` sube a `>=3.9` (lo exige `google-genai`).
- **Documentación:** el README y los tutoriales describen los tres proveedores y el flujo sin API, y recomiendan `gemini-flash-latest` en lugar de `gemini-2.5-flash` (Google ha anunciado la retirada de los modelos `gemini-2.5-*` de la API de Gemini en octubre de 2026; `gemini-flash-latest` apunta siempre al modelo Flash vigente). La referencia de la API incluye los módulos `ai_providers`, `question_parsing` y `web_chat_assistant`.
- **Comprobación de las preguntas antes de generar un examen:** si alguna pregunta seleccionada no tiene enunciado, le falta una opción o su "Respuesta correcta" no es una letra de la A a la D, se avisa indicando la fila del Excel, el número, el tema y el problema, y no se genera ningún archivo. La letra admite variantes como " B ", "b)", "(c)" o "D.".
- **"Añadir preguntas sin duplicados" compara como "Unificar bancos":** ignora mayúsculas y espacios sobrantes y compara las respuestas sin importar su orden, por lo que puede añadir menos preguntas que antes. Las preguntas repetidas dentro del propio archivo revisado se añaden una sola vez.
- **Nombres de archivo de los exámenes:** los caracteres no válidos (`/ \ : * ? " < > |`) del nombre de la asignatura, examen, curso o tipo se sustituyen por `_` (p. ej. "Física I/II" da `examen_Física I_II_…`); los títulos y cabeceras conservan el texto original.
- **XML de Moodle con el texto completo:** el enunciado y las respuestas se escapan como HTML (los signos `<`, `>` y `&` se ven tal cual y se respetan los saltos de línea; las etiquetas HTML escritas en el banco se muestran como texto). La categoría ya no termina en ` -` cuando no hay texto adicional y coincide con la que sugiere la aplicación.

### Arreglado
- **Tema sin extensión:** la columna `Tema` se obtiene del nombre del archivo sin su extensión, sea cual sea (antes solo se quitaba `.pdf` en minúsculas y quedaban, p. ej., `.PDF` o `.png`).
- **Duplicados entre fragmentos:** se descartan las preguntas repetidas (mismo tema, enunciado y opciones) obtenidas en distintos fragmentos o intentos de una misma generación; las preguntas con el mismo enunciado y opciones distintas ("Señala la afirmación correcta...") se conservan.
- **Fragmentos de PDFs con el mismo nombre:** en el flujo sin API, dos fuentes con el mismo nombre en carpetas distintas ya no comparten (ni sobrescriben) los PDF de sus fragmentos.
- **Respuestas largas en el Excel de prompts:** las respuestas que no caben en una celda se guardan en un `.txt` referenciado con una ruta relativa al Excel, de modo que la importación funciona aunque la carpeta se mueva o el directorio de salida sea relativo.
- **Fragmentos sin texto:** en modo `text`, los fragmentos sin texto extraíble (páginas escaneadas) se omiten con un aviso que sugiere usar el modo `image` o `pdf`.
- **DOCX revisado con dos puntos:** `QuestionBankManager.read_questions_from_docx` ya no trunca los enunciados que contienen `:` al convertir el DOCX revisado en XLSX.
- **Selección de archivos fuente:** volver a pulsar "Seleccionar Archivos" ya no pega las rutas nuevas a las anteriores sin separador (ahora se añaden a la lista sin repetirse) y se admiten nombres de archivo que contienen comas.
- **Rueda del ratón en Generar Preguntas:** las áreas de texto y las tablas de la pestaña se desplazan con la rueda del ratón (antes la rueda solo movía la pestaña completa).
- **Diálogos de Excel en Linux/macOS:** los diálogos para elegir archivos Excel vuelven a listar los `.xlsx` (el patrón `*.xlsx;*.xls` no se interpretaba bien fuera de Windows).
- **Edición de prompts:** **"Editar"** abre ahora el texto del prompt seleccionado (antes aparecía vacío) y los cambios en los prompts predeterminados (PRL, PM) se guardan en `custom_prompts.json`.
- **Banco obsoleto al generar varios exámenes en la misma sesión:** el banco se lee de nuevo en cada generación. Antes, la pestaña Generar Exámenes reutilizaba el primer banco leído aunque se eligiera otro archivo o se editara en Excel y, con "Actualizar Excel", podía sobrescribir el banco seleccionado con los datos del anterior.
- **"Actualizar Excel" marca solo las preguntas del examen:** el uso se marca por la fila seleccionada y no por "Número de pregunta", que se repite en los bancos unificados (antes podía marcar preguntas que no estaban en el examen) y que ya no es obligatorio.
- **Banco no actualizado sin aviso:** si "Actualizar Excel" no puede guardar el banco (p. ej. porque está abierto en Excel), la aplicación lo avisa en lugar de mostrar "Exámenes generados correctamente". Los errores de validación de las preguntas ya no van precedidos de un mensaje genérico sobre preguntas "Aceptables".
- **"Menos usadas":** funciona en bancos sin la columna "Veces usada en examen" y elige primero las preguntas sin usos registrados (celda vacía = 0); en caso de empate se respeta el orden del banco.
- **Temas escritos como números:** los temas guardados en Excel como número (1, 2…) coinciden con el diccionario "Tema:Cantidad" de la interfaz y se ignoran los espacios sobrantes.
- **Selección vacía:** si no se pide ninguna pregunta (todos los temas a 0 o diccionario vacío) se muestra un aviso en lugar de un error técnico o de un examen con todo el banco.
- **XML de Moodle con opciones numéricas o vacías:** ya no falla al exportar el texto completo si alguna celda contiene un número (p. ej. 1995) o está vacía.
- **Columnas de uso con texto:** actualizar el uso funciona aunque una columna `_uso` contenga texto escrito a mano (se conserva) o VERDADERO/FALSO; ese texto cuenta como 0 en "Veces usada en examen" (antes fallaba con pandas 3).
- **DOCX revisado:** al convertirlo a Excel ya no se pierden las líneas en las que continúa el enunciado, una opción o el texto relevante (se unen con un salto de línea) ni se borran "A)", "C)"… cuando aparecen dentro del texto de una opción.
- **Scripts:** con `check=True` se acepta "si", "sí" o "s" y la previsualización se guarda junto a los exámenes; `add_reviewed_questions_to_existing_excel` guarda `<banco>_actualizado.xlsx` junto al banco y devuelve esa ruta; generar exámenes o convertir un DOCX indicando solo el nombre del archivo (sin carpeta) ya no falla.
- **Corrección con XML de texto completo:** un XML de Moodle generado con el texto completo de las respuestas se corrige bien (antes todos los alumnos sacaban 0).
- **Varias plantillas al corregir desde respuestas (xlsx):** cada alumno se corrige con la plantilla de su tipo de examen (columna `Tipo_Examen_Usado`, `Tipo_Examen` o `Tipo`); si hay varias plantillas y el fichero no tiene esa columna, se avisa en lugar de corregir a todos con la primera.
- **IDs numéricos y alumnos sin ID:** los IDs ya no se convierten en `12345678.0`, por lo que los alumnos se emparejan bien en la nota final, la comparación y la integración OCR (el fichero de Moodle conserva su ID original). Los alumnos sin ID ya no comparten justificaciones ni punto extra con otros, una nota OCR siempre se escribe al alumno identificado en su hoja y la integración de Moodle con "deduplicar por ID" ya no fusiona a los alumnos sin ID.
- **Mapeo de columnas en "Corregir Exámenes":** se usa también para leer los listados de matriculados (p. ej. un export de Moodle en inglés), en lugar de fallar con "Error: 'First name'".
- **Asistencia de cualquier año:** las columnas de sesiones se reconocen sea cual sea el año (antes solo 2026); si no se encuentra ninguna, se muestra un aviso en lugar de un error.
- **Justificaciones con nombres compuestos:** las faltas justificadas se aplican también a alumnos con nombre compuesto (p. ej. "María José").
- **OCR robusto:** una foto ilegible o una hoja cuyo tipo de examen no se detecta ya no detienen el lote; aparecen en `incidencias.xlsx` (con el tipo sugerido) y se escriben todos los resultados. La tabla de incidencias también señala las marcas dudosas o sin resolver al corregir desde la interfaz.
- **Matrícula fusionada:** se guarda como `matriculados_fusionados.xlsx` y nunca sobrescribe uno de los ficheros de matriculados del profesor.
- **Corregir desde respuestas:** acepta el `respuestas.xlsx` del OCR, lista las filas no corregidas en `incidencias_respuestas.xlsx` y en un aviso, falla si no se pudo corregir ninguna fila y ya no escribe horas de inicio y fin inventadas.
- **Nota final ponderada:** detecta las columnas de ID y nombre de cada fichero (DNI, Apellidos...), une las filas sin ID con el alumno del mismo nombre, trata como exámenes distintos los ficheros con el mismo nombre en carpetas diferentes y, en la interfaz, admite pesos en porcentaje (`60%`) y avisa de un peso no válido.
- **"Comparar y combinar (sobrescribir)":** ya no falla cuando un valor cambia de tipo (p. ej. de 8 a "9,50", o de vacío a "asiste").
- **Plantillas duplicadas:** dos plantillas XML distintas para el mismo tipo de examen (p. ej. GIM y GITI ambas "1A") producen un error en lugar de usar una de ellas en silencio.
- **Grupo por nombre de archivo:** el grupo se detecta por palabras completas ("Higiene_Industrial_GIM.xlsx" es GIM, no GITI-GIE-GIEI).
- **Sesiones y tareas de corrección:** cargar una sesión vacía los campos que están vacíos en ella y restaura también los de nota final, comparación e integración; solo se ejecuta una tarea de corrección a la vez.

### Seguridad
- **Sin `eval()` sobre la salida del modelo:** las respuestas del modelo se interpretaban con `eval()`, de modo que un texto malicioso en una respuesta (o pegado desde un chat) podía ejecutar código. Ahora solo se decodifican con `json` y `ast.literal_eval`: la salida del modelo nunca se ejecuta.
- **Sesiones de corrección:** "Cargar sesión" carga siempre el `.json` y nunca abre un `.pkl`, que podría ejecutar código si procede de otra persona.
- **Claves API fuera de la carpeta de trabajo:** **"Guardar Clave"** guarda `config.json` (proveedor, claves y modelos) en la carpeta de configuración del usuario (`%APPDATA%\pyexamgenerator\config.json` en Windows, `~/.config/pyexamgenerator/config.json` en macOS y Linux), accesible solo para el usuario donde el sistema lo permite, en lugar de en la carpeta desde la que se abre la aplicación (a menudo sincronizada en la nube). Así la clave ya no "desaparece" al abrir la aplicación desde otra carpeta y se puede guardar aunque la carpeta de trabajo sea de solo lectura. El `config.json` de la carpeta de trabajo de versiones anteriores se sigue leyendo mientras no exista el nuevo y se copia a la nueva ubicación en el siguiente guardado, sin borrarlo (el mensaje de confirmación avisa de ello). Las variables de entorno siguen teniendo prioridad y se conservan las claves de proveedores desconocidos. La plantilla de "Generar Exámenes" usa la misma carpeta como ubicación central, ahora también en macOS y Linux. Nuevo módulo `pyexamgenerator.user_config` (sin Tkinter), con pruebas en `tests/test_user_config.py`.

## [0.3.0] - 2026-09-15

### Añadido
- **Modo unión/estricto en integración OCR (GUI + API):** la sección de integración en la pestaña **Corregir Exámenes** incorpora un check para elegir entre **unir** (añadir alumnos OCR no presentes en teoría) o **modo estricto** (bloquear no emparejados). La preferencia se guarda/carga en la sesión de corrección (`append_unmatched_ocr`) y se propaga a `OCRIntegrationConfig.append_unmatched_students`.
- **Reporte de incidencias de integración OCR:** `OcrGradeIntegrator` expone `last_integration_summary` y `last_integration_incidents_df`, `ExamCorrectionAPI.integrate_ocr_grades(...)` guarda el resumen en `results["ocr_integration_summary"]` y exporta `incidencias_integracion_ocr.xlsx` cuando hay filas bloqueadas.
- **Cobertura de pruebas para integración OCR y preservación de ID:** se añaden casos en `tests/test_grading_unit.py` y `tests/test_grading_session_and_grades.py` para validar modo unión/estricto, eliminación de filas resumen, exportación de incidencias y conservación de IDs con ceros iniciales.
- **Popups copiables en la GUI:** los cuadros `showinfo`, `showwarning` y `showerror` ahora se muestran con texto seleccionable/copiable (botón **"Copiar"** y atajo `Ctrl+C`), útil para pegar errores completos en incidencias o soporte.
- **Tabla para tipos forzados por imagen (OCR):** en **Corregir Exámenes**, además del campo de texto `imagen=tipo`, ahora se puede abrir una tabla con columnas **Imagen / Tipo asignado / Ruta** para asignar el tipo por fila desde el botón **"Asignar tipos en tabla..."**.
- **Generar XML Moodle desde un examen XLSX existente:** Nuevo método `ExamGenerator.generate_moodle_xml_from_existing_exam_xlsx(...)` para convertir directamente un `*_completo.xlsx` en XML de Moodle sin volver a generar el examen completo.
- **Conversión XLSX→XML en la pestaña Generar Exámenes:** La GUI añade la sección **"Generar Moodle XML desde XLSX de Examen"** (selección de `*_completo.xlsx`, ruta XML de salida opcional, penalización, texto extra de categoría y modo de XML no blanco).

- **Identificación del alumno en cada página:** El DOCX del alumno incluye en la cabecera repetida de cada página huecos para Nombre, Apellidos, DNI/NIE y Firma, además de conservar la tabla de datos de la hoja de respuestas.

- **Modo unión por defecto en integración OCR:** `OCRIntegrationConfig.append_unmatched_students` pasa a `True` por defecto para reflejar el flujo habitual (teoría Moodle + manuscritos OCR), añadiendo filas OCR no presentes en teoría salvo que se active explícitamente el modo estricto.

### Arreglado
- **Limpieza automática de filas de promedio/resumen antes de integrar OCR:** `OcrGradeIntegrator` elimina filas no pertenecientes a alumnos (p. ej. `Promedio general`) en el xlsx general, tanto en formato clásico como en formato de totales de cuestionario, y lo refleja en el contador `general_summary_rows_removed`.
- **Conservación de IDs con ceros iniciales en integraciones de notas:** la lectura de Excel evita la inferencia que perdía ceros a la izquierda (`001234 -> 1234`) y `_normalize_id` mantiene el valor textual del identificador en las salidas integradas.
- **Avisos de incidencias más claros en GUI:** al corregir OCR o integrar teoría+OCR, la interfaz muestra avisos específicos cuando hay incidencias OCR, filas bloqueadas en integración o filas resumen eliminadas automáticamente.
- **Ultimo recurso OCR con carpeta temporal configurable:** cuando fallan `cv2.imread(...)` y el fallback `np.fromfile + cv2.imdecode`, `AnswerSheetExtractor` copia la imagen a una carpeta temporal configurable y reintenta desde ahi; por defecto usa `~/Desktop/pyexamgenerator_temp` y limpia las copias al terminar. La GUI de **Corregir Exámenes** añade el campo **"Carpeta temp OCR (fallback)"**.
- **Tipo de examen único en OCR:** si el OCR no detecta el tipo en una hoja, pero solo hay una plantilla XML cargada (por ejemplo, solo `A`), `ImageExamGrader` usa automáticamente ese único tipo en lugar de fallar con *"Could not determine exam type"*.
- **Tipos forzados por nombre o ruta en OCR:** `ImageExamGrader` ahora acepta claves de `forced_type_by_image` tanto por nombre de archivo como por ruta completa (normalizando barras y mayúsculas/minúsculas), lo que evita colisiones cuando hay imágenes con el mismo nombre en carpetas distintas.
- **Lectura de imágenes OCR en rutas Windows con Unicode:** `AnswerSheetExtractor` añade un fallback `np.fromfile + cv2.imdecode` cuando `cv2.imread(...)` falla, evitando errores *"Could not read image"* en rutas con acentos/caracteres especiales (p. ej. carpetas de OneDrive).
- **Tipos de examen con letra sola (`A`, `B`) en corrección:** la inferencia del tipo desde XML y el parseo de columnas Moodle en integración (`Cuestionario:..._Tipo A (Real)`) aceptan ahora tanto formatos `A/B` como `1A/1B`.
- **Fracciones de penalización compatibles con Moodle:** Al exportar XML, las penalizaciones se ajustan automáticamente a opciones válidas de Moodle (p. ej., `-33` se normaliza a `-33.3333333`) para evitar omisión de preguntas al importar.
- **Scroll con rueda en pestañas largas de GUI:** Se corrige la rueda del ratón para que desplace aunque el cursor esté sobre campos o controles internos en **Gestionar Banco de Preguntas** y **Generar Preguntas**.
- **Columna de uso del `*_completo.xlsx`:** El XLSX generado junto al examen ahora añade al final la columna de uso del examen actual (`<examen>_<curso>_uso`) con valor `1` en todas sus filas, en lugar de dejar visibles valores históricos heredados del banco para las preguntas seleccionadas.
- **Integración de notas OCR en formato *quiz-totals*:** `OcrGradeIntegrator` no conseguía volcar las notas manuscritas cuando un mismo tipo de examen existía en varios grupos (p. ej. `GIM` y `GITI-GIE-GIEI`), porque el mapa `Número de ID → grupo` no casaba con el índice del fichero de Moodle (`Nombre de usuario`). Ahora desambigua usando el `Grupo_Principal` que viene en la propia fila OCR, de modo que las notas aterrizan en la columna de cuestionario correcta.
- **Estado case-insensitive:** El filtro de preguntas con estado "Aceptable" ahora acepta variantes como "aceptable" en generación de exámenes y en fusión de bancos.
- **Tooltips persistentes en GUI:** Se corrige el comportamiento de tooltips que podían quedar visibles al salir del widget o cerrar la aplicación, reforzando la destrucción y el manejo de eventos de cierre.
- **Orden canónico único por tipo:** Generación de exámenes con un orden canónico por tipo, reutilizado en enunciados, hoja de respuestas y exportación XML de Moodle.
- La tabla de la hoja de respuestas muestra la numeración `01..N` de forma consistente.
- Los nombres de pregunta en XML (`Pregunta 01`, `Pregunta 02`, ...) usan dos dígitos para mantener homogeneidad visual y trazabilidad con la hoja de respuestas.
